## Security evidence and corrected failure paths

API tests use ephemeral RSA keys and static OIDC metadata. They exercise valid tokens, wrong issuer/audience/signature/scheme, unsigned tokens, expired and not-yet-valid tokens, missing expiration/subject/scope and scope-prefix confusion. Disabled identity denies protected test routes, invalid enabled configuration fails startup, and the production route inventory contains only the three documented diagnostics. These tests do not establish live ZITADEL integration or tenant isolation.

An HTML `Accept` header initially bypassed the registered JSON Problem Details writer: Production propagated the exception and Development could render its exception page. The exception boundary now explicitly falls back to a fixed JSON Problem Details response. Regression cases pass for JSON and HTML requests in both environments; client responses contain neither the test secret marker nor stack details. Exceptions are logged once with type and trace ID, without exception messages.

Frontend formatting initially traversed generated Angular output after a build. A frontend-specific Prettier ignore file now keeps the formatting gate limited to reviewable sources. The full verification run was repeated after both corrections.

The development credential generator created random passwords in ignored `infra/compose/.env` without overwriting an existing file. A directory-wide Gitleaks check correctly detected those two local credentials; it was not a clean scan. No `.env` secret exclusion was added. Git-history/staged checks and the tracked-file guard establish the repository result; neither claims that the local filesystem contains no secrets. Generated output, caches, Terraform state and local env files are untracked and ignored.

## Unverified or deferred

- **Container startup/health and image CVEs:** Docker CLI/Compose work, but the engine fails with `open //./pipe/docker_engine: The system cannot find the file specified.` Both exact image tags were found in registry manifests; no image pull, running-container health check or container vulnerability scan is claimed. CI includes disposable PostgreSQL/RabbitMQ startup and health checks; the developer must start Docker Desktop to verify locally.
- **GitHub-hosted execution:** CI was reviewed and actionlint-checked, with its build/test/configuration/scanner commands run locally. The workflow itself has not run on GitHub; nothing was pushed. Linux runner behavior and container health remain to be observed there.
- **External identity and authorization:** no live OIDC discovery, browser PKCE, memberships, role changes or tenant persistence exists yet. The initial Angular test is not a browser end-to-end or accessibility audit.
- **Object storage:** no MinIO image, replacement, storage SDK or fake runtime adapter was introduced. The port/configuration is provider-neutral, S3 is planned, and the local provider decision is deferred in ADR 0005.
- **Observability:** tracing/metrics registration and safe logging are present; an OTLP collector, exported signal content and operational SLOs were not exercised.
- **AWS:** authentication was not attempted. The preflight was statically checked and exercised with a mock only. The developer must later run the authenticated preflight locally using temporary credentials. Terraform contains no resources, data sources or remote backend; no apply, deployment, IAM/OIDC setup or AWS modification occurred.
- **Security coverage:** scanners report only what their configured scope and databases detect. No independent penetration test, exhaustive SAST audit, image scan, SBOM publication or compliance certification is claimed. Roslyn analyzers, strict frontend compilation and the recorded tests are the initial static and behavioral gates.

## Follow-up

Phase 1 should introduce the smallest identity/organization membership slice with reviewed PostgreSQL migrations and server-side authorization. Require same-tenant permissions, cross-tenant rejection, removed membership and changed-role tests before adding incident or evidence endpoints. Resolve local object storage only after supported candidates and tradeoffs are reviewed. Revisit the threat model for each new boundary.
